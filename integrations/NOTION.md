# Notion meeting notes

JARVIS can record a conversation as meeting notes in Notion — **only when you ask**.

| Say | What happens |
|---|---|
| "Mulai catat rapat" / "Start meeting notes for the weekly review" | Creates a Notion page and starts recording |
| "Status catatan rapat?" | Reports how many lines are recorded and synced |
| "Selesai catat" / "Stop recording" | Writes summary, decisions and action items, marks the page complete |

## Page layout

```
🎙️ Recording — started 09:00        → ✅ Meeting ended 09:00–09:42 · 36 turns
## Summary
   <3–6 sentence summary>
   ### Decisions        • …
   ### Action items     ☐ task — owner — due date
──────────
## Transcript
   09:01  You: …
   09:01  JARVIS: …
```

The transcript is appended every 20 seconds (or sooner after 6 new lines), so a crash loses at most a few lines. The summary is generated by Gemini at the end, in your language, from the transcript only.

## Setup

1. Go to https://www.notion.so/profile/integrations and create an **internal integration** named JARVIS. Give it *Read content*, *Update content* and *Insert content* capabilities, then copy the secret (`ntn_…`).
2. In Notion, create a page (e.g. *JARVIS Meeting Notes*) or a database with a title column and optionally a date column.
3. Open that page or database → `•••` → **Connections** → add **JARVIS**.
4. Add both values to `config/api_keys.json`. If you use the installed app, the file is `~/Library/Application Support/JARVIS/app/config/api_keys.json`:

   ```json
   {
     "gemini_api_key": "…",
     "notion_token": "ntn_…",
     "notion_target": "https://www.notion.so/JARVIS-Meeting-Notes-0123456789abcdef0123456789abcdef"
   }
   ```

   `notion_target` accepts a page or database URL or ID. A database gets one row per meeting, with the date filled in.

5. Restart JARVIS and say "mulai catat rapat".

## Privacy and safety

- **Explicit start only.** JARVIS never records on its own and says out loud when recording starts.
- **Third-party storage.** The transcript and summary are stored in your Notion workspace (Notion's cloud). The summary is generated by Gemini, which already processes the live conversation.
- **Private Brain redaction.** Any exchange in which the `private_brain` tool ran is replaced by `[redacted: private knowledge — not recorded]` in Notion, in the local copy and in the summary input. Configure the tool list with `sensitive_tools` in `config/meeting_notes.json`.
- **Local copy.** Each meeting is also written to `~/Documents/JARVIS/Meetings/<date>_<title>.md` (file mode 600). Turns that could not reach Notion are kept there and flagged.
- **Token handling.** The token is never logged or included in error messages.

## Settings (`config/meeting_notes.json`)

| Key | Default | Meaning |
|---|---|---|
| `flush_interval_seconds` | 20 | How often pending lines are sent to Notion |
| `flush_min_turns` | 6 | Send sooner once this many lines are pending |
| `sensitive_tools` | `["private_brain"]` | Tools whose exchanges are redacted |
| `local_backup` | `true` | Also keep a Markdown copy |
| `backup_dir` | `~/Documents/JARVIS/Meetings` | Where local copies go (honours `JARVIS_DOCUMENTS_DIR`) |
| `summary_model` | `gemini-flash-latest` | Model used for the final summary |
| `max_summary_characters` | 60000 | Transcript tail sent to the summarizer |
